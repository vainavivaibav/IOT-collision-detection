INCIDENT LIFECYCLE MANAGEMENT

From Vehicle Motion to Cloud Monitoring and Planned SMS Alerts

Detecting Sudden Movement

A sudden impact or strong vibration can be difficult to observe remotely. Without automatic sensing and location reporting, an event may not be visible to the people monitoring the system.

  • Movement events may go unnoticed without sensor-based detection.
  • Vibration and acceleration data need to be collected at the robot car.
  • Event records are more useful when paired with GPS coordinates.

SAFERIDE System Architecture

The design assigns the ADXL345 and SW-420 to ESP32 #1 for collision sensing. ESP32 #2 is designed to receive event data over Wi-Fi and use the NEO-6M for coordinates; the intended cloud route uses a Wi-Fi hotspot to reach the existing Render API and PostgreSQL dashboard. A separate planned SIM800L GSM module is intended to SMS collision/location details to a designated contact. Physical wiring and transmission are not verified.

Integration status: The frontend can read stored records from the Render API. Physical ESP32-to-cloud transmission is not verified. The SIM800L is a separate planned SMS path; check its wiring and power with a multimeter before integration. SMS delivery is not implemented or verified.

ESP32 #2 • Wi-Fi event handoff • NEO-6M
